# Esports platform — working notes for Claude

Production esports site for India (Free Fire, BGMI, Valorant). **docs/SPEC.md is the source of truth** for features and rules; docs/PHASES.md is the build plan; docs/PROGRESS.md logs what each phase delivered; docs/DECISIONS.md records every spec ambiguity resolved. Never delete or rewrite SPEC.md or PHASES.md.

## Stack (do not substitute)

- Next.js 16 (App Router, TypeScript strict), Tailwind CSS v4, shadcn/ui (Radix base, `components/ui`)
- Prisma 7 + PostgreSQL via `@prisma/adapter-pg`; generated client in `generated/prisma` (gitignored, `prisma generate` on postinstall)
- Firebase Phone Auth on the client for OTP only; our own session = signed JWT (jose, HS256) in an httpOnly cookie
- Zod for all input validation; server actions or route handlers for mutations
- Razorpay Checkout for entry fees (DECISIONS M43; Cashfree PG + Payouts remain as an alternative); Web Push via VAPID (Phase 7)
- Vitest (unit + DB integration), Playwright (e2e, mobile viewport)
- Vercel hosting + Vercel Cron

Next.js 16 specifics that differ from older versions: `middleware.ts` is now **`proxy.ts`**; `params`, `searchParams`, `cookies()`, `headers()` are **async**; use the global `PageProps<"/route">` / `LayoutProps<"/">` types (generated by `next typegen`); `revalidateTag(tag, profile)` needs two args. Read `node_modules/next/dist/docs/` before using an unfamiliar API.

## Folder conventions

- `app/` — routes only. `app/(site)/` = public site with header/footer; `app/admin/` = admin panel; `app/api/` = route handlers (auth, webhooks, cron, files). Keep pages thin: fetch via `server/`, render via `components/`.
- `components/` — React components. `ui/` is shadcn (edit sparingly; tap targets were raised to 44px), `layout/`, `game/`, `admin/`, `common/`, feature folders.
- `lib/` — pure, framework-free logic (no DB, no Next imports except `lib/params.ts`): game config, time/IST helpers, validators, points engine, state machines. Must be unit-testable.
- `server/` — server-only code (`import "server-only"`): db client, session, auth guards, services (one file per domain), providers behind interfaces (storage, payments, OTP verifier, notifications). Server actions live next to their route as `actions.ts` and are thin wrappers around `server/services/*`.
- `prisma/` — `schema.prisma`, `migrations/`, `seed.ts`.
- `tests/unit` (pure), `tests/integration` (real Postgres test DB), `e2e/` (Playwright).

## Coding rules

- **Every mutation validates input with Zod on the server and checks role/ownership** via `requireUser` / `requireModerator` / `requireAdmin`. Services take an explicit `actor` so they are testable without Next request context.
- **No secrets in client code.** Only `NEXT_PUBLIC_*` vars may be read in client components. Room credentials, phone numbers, payout details and raw webhooks never go into page props for anyone but the owner/staff.
- **Time:** store UTC (`DateTime` columns), display IST everywhere via `lib/time.ts`. Admin forms take IST input and convert.
- **Money:** integer paise only (`*Paise` columns). Never floats.
- **State transitions** go through the state-machine helpers; illegal ones are rejected server-side and every transition writes `AuditLog`.
- Mobile-first layouts, dark only (static `dark` class and `color-scheme` on `<html>`; no theme provider), 44px minimum tap targets (`min-h-tap`), visible focus states, aria labels on icon-only buttons; a link's accessible name must contain its visible text (no `aria-label` that rewords it).
- **Design is fixed**: `docs/design/pages/*.png` (home-desktop.png first) is the visual source of truth; never edit `docs/design/`. Colours only from the Design reference tokens in `app/tokens.css` (`bg-background`, `bg-surface`/`bg-card`, `border-border`, `text-gold`/`bg-gold`, `hover:bg-gold-hover`, `text-muted-foreground`, `bg-game-*`, `text-success`, `text-destructive`) — a unit test fails on any other hex. Headings use Barlow Condensed (`h1–h3` automatically, or `font-heading`), body Inter. Cards: `card-ds` / `card-ds-interactive` (12px radius, 1px border, gold border on hover/active). Buttons: `default` = solid gold, `gold-outline`, `outline`. Filter chips: `chipClass()` in `lib/ui.ts`. Icons: lucide-react, except social-network logos, which come from simple-icons via `BrandIcon` (`components/common/brand-icon.tsx`, DECISIONS M24; use `currentColor`, not brand hex).
- **Artwork**: every image from the design goes through `<Artwork name>` (`components/common/artwork.tsx`); names are listed in `lib/artwork.ts`. Files dropped into `docs/design/assets/<name>.png` are copied to `public/art/` and listed in `lib/art-manifest.ts` by `scripts/sync-art.mjs` (runs on install/dev/build/typecheck/test); missing files render a same-size placeholder. Never draw game logos, characters or partner logos; game names are styled text (`GameBadge`); the partners row shows only admin-uploaded sponsor logos.
  Stacked art (a character over its background) passes `layer` on the top `<Artwork>` so a missing top file stays transparent.
  `sync-art` (sharp) builds `<name>-<w>.webp` at fixed widths plus a ≤1280px PNG fallback and records sizes in the manifest; `<Artwork>` renders `<picture>` (WebP srcset + PNG img). Always pass a `sizes` that matches the slot, position the subject with `object-*` in `className`, use `priority` only for the LCP image and `lowPriority` for other above-the-fold art; CSS backgrounds use `image-set()` with `artworkWebpFor()`. `e2e/artwork.spec.ts` enforces no placeholders, WebP only and ≤300 KB per image on phones.
- **First-paint budget**: keep the shared shell light. No global Radix providers (no TooltipProvider); navbar dropdowns are WAI disclosures (`components/layout/nav-links.tsx`), not DropdownMenu; interaction-only UI (mobile menu sheet, toaster) is loaded with `next/dynamic` on demand; Sentry's browser SDK is imported lazily in `instrumentation-client.ts`. Horizontal snap rows need matching `scroll-px-*` so they don't scroll themselves on load (that stops Chrome's LCP tracking).
  - Client components never reach Zod or other server-only code: import constants and helpers from the Zod-free modules (`lib/match-modes.ts`, `lib/input-rules.ts`, `lib/content-keys.ts`), not from `lib/match-schema`, `lib/validators`, `lib/content` or `lib/payments`. `npm run check:client-imports` enforces this in CI (server-action modules are the allowed boundary).
  - Client bundle budget: CI runs `npm run bundle:check` after the build and fails on >20% growth of any chunk or route, or on a server-only library in a client chunk. For intended growth, commit a new baseline in the same PR: `npm run build && npm run bundle:baseline`.
  - Every internal link is `IntentLink` (`components/common/intent-link.tsx`: prefetch on hover/touch/focus, never on load). ESLint forbids importing `next/link` anywhere else, and `e2e/prefetch-budget.spec.ts` fails if any route prefetches on first load.
  - Icons repeated on every card use `SpriteIcon` (`components/common/icon-sprite.tsx`, symbols rendered once in the site layout); add new ones to its map.
  - Non-urgent client work (analytics, service worker) runs through `afterLoad()` (`components/common/after-load.ts`).
  - Below-the-fold page sections sit in their own `<Suspense>` so React hydrates them as separate tasks.
  - "₹" renders from a local font (`"Rupee Local"` @font-face in `app/globals.css`, unicode-range U+20B9); keep it first in any new font stack.
  - Lighthouse: report the **median of 5** mobile runs against a production build (`next start`), and also through an HTTP/2 proxy (production is HTTP/2); see docs/PROGRESS.md "Lighthouse" for the commands.
- **Headings with icons**: `PageHeader` takes `icon` (gold lucide icon) and `tag` ("Current season"); podium places use `PlaceIcon`/`RankBadge` (`components/leaderboard/rank-badge.tsx`), never emoji; avatars use `PlayerAvatar`.
- **Generated images** (OG cards, icons): colours come from `lib/design-tokens.ts` (`DS`, `GAME_HEX`; a test keeps it equal to `app/tokens.css`), fonts from `ogFonts()` (`server/og-fonts.ts`), artwork via `artworkDataUri()` (`server/art-data.ts`). Satori quirks: no `inset` shorthand (use top/left/right/bottom), WOFF/TTF only, and put glyphs Barlow lacks (₹) in their own span. New image routes must be added to `outputFileTracingIncludes` in `next.config.ts`.
- **/scrims** (scrims-desktop.png): all filter/sort/date logic is pure in `lib/scrims-filter.ts` (URL query ↔ `ScrimsQuery` via `parseScrimsQuery` / `scrimsHref`); card status comes from `scrimStatus()`, which wraps the registration rules' `cardAction` — never re-implement registration rules in UI code. Filter forms are GET forms that also work without JS (`useQueryFormSubmit` in `components/scrims/filter-form.tsx`). Header menus use `useDisclosure` (`components/layout/use-disclosure.ts`).
- **Home page** (home-desktop.png): hero stats, the live-stats toggle, the trailer link and the taglines are admin settings (`HOME_SETTING_KEYS` / `homeSettingsFromRows` in `lib/content-keys.ts`, `getHomeSettings`/`saveHomeSettings` in `server/services/content.ts`); stat display rules are `resolveHeroStats` in `lib/home.ts`. Carousel timing lives in `lib/carousel.ts` (pure, fake-timer tested). "Last Week's Winners" reads published tournament podiums (`getLatestWinners`), never admin carousel items. The game-strip card is shared (`components/game/game-strip-card.tsx`).
- **E2E data**: create matches relative to the current time with `createOpenScrim` / `istAt` (`e2e/support/fixtures.ts`), never rely on the seed's fixed IST times; give every test user a phone number no other spec uses (grep `e2e/` first). `e2e/support/seed-extras.ts` adds a team and last week's tournament with published winners on every run; past tournaments for tests come from `createPublishedTournament` (idempotent per game and week).
- Per-game accents (`bg-game-*`, `text-game-*`, `border-game-*`) only on that game's cards/pages, via `GAME_CONFIG[game].accent` in `lib/games.ts`. Brand name is "Esports" (`lib/site.ts`), matching the design.
- Missing third-party credentials → the provider falls back to a local stub behind the same interface (dev/test only; production refuses to start with a stub).
- Prefer small files and small functions; prefer boring, well-known libraries.
- Server actions: `"use server"` file next to the route, body wrapped in `runAction(() => ..., "toast message")` from `server/action.ts`; first line calls `requireUser()`/`requireModerator()`/`requireAdmin()`; then a service in `server/services/*` that takes `(actor, input: unknown)`, calls `assertUser/assertModerator/assertAdmin(actor)` from `lib/roles.ts` and `parseInput(zodSchema, input)`. Client components call actions through `useAction` (`components/common/use-action.ts`), which toasts every outcome.
- Admin pages: call `await requireStaffPage("/admin/<section>")` at the top of every page (layouts don't re-run on client navigation).
- Tests: `tests/unit` (pure), `tests/integration` (real Postgres `TEST_DATABASE_URL`, `resetDb()` + factories in `tests/helpers/db.ts`), `e2e/` (Playwright against `E2E_DATABASE_URL`, reset + seeded in `e2e/support/global-setup.ts`; log in with `loginViaUi` + stub code 123456). Every server mutation needs a validation test and a role test.
- The package is ESM (`"type": "module"`).
- Migrations: `prisma migrate dev` refuses to run non-interactively when it wants to confirm a warning. Then generate SQL with `npx prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script > prisma/migrations/<UTC timestamp>_<name>/migration.sql` and apply it with `npx prisma migrate deploy`.
- `loading.tsx` commits a 200 status before the page runs, so `notFound()` inside that page becomes a soft 404. Only add skeletons to pages that cannot 404 (scope them with a route group, e.g. `leaderboard/[game]/(current)/`); validate URL slugs in `proxy.ts`.
- Tournament sign-ups are `Match` rows with `isEntryList = true`; exclude them from anything that lists playable matches.
- Long file contents: write them with the Write tool, not shell heredocs (the shell wrapper mis-parses some quotes).

## Commands

| Task | Command |
| --- | --- |

Local Postgres: Docker container `esports-postgres` on port 5440 (see docs/HANDOFF.md). Prisma blocks `migrate reset` for AI agents without explicit user consent — never rely on it; tests truncate tables instead.
